# re-go-dianping 实现 PUT /shop 商铺更新接口

## 更新语义（定案）

- **部分更新（patch）**：请求体只传要改的字段，没传的字段保持原值。靠指针 nil 区分"没传"和"传了合法零值"（如 `sold: 0` 要能真的写库——这是 GORM 的经典坑）。
- **可更新字段**：把 `ShopInput` 从现在 5 个扩到全量 12 个（name、typeId、images、area、address、x、y、avgPrice、sold、comments、score、openHours）+ 非指针的 `id`，与 go-dianping 参考答案对齐。创建接口顺带受益（创建时也能传 images 等了）。
- **校验方式**：先读旧商铺 → 合并补丁得到完整新状态 → 对**合并后的完整实体**跑现有 `validateShop`（只 patch name 也会校验库里旧的坐标，保证不变式）。
- **商铺不存在** → 404（复用 `gorm.ErrRecordNotFound` 的映射）。
- **typeId 只有变化时才查** `ShopTypeExists`（类型没变省一次 DB）。
- **缓存失效放在 SQL 提交之后**：`cache.Invalidate`（INCR 版本 + DEL 数据 key，Lua 原子）——这是你学的那套版本机制的真正用武之地。失败只记日志不报错（与现有 ShopCreate 风格一致，脏缓存受 5 分钟 TTL 兜底；go-dianping 参考答案是返回 5xx 让客户端重试，留给你之后对照升级）。
- **GEO 同步**：坐标变化时 `GEOADD` 按 member 幂等覆盖，无需删；typeId 变化时 `ZRem` 旧集合 + `GeoAdd` 新集合（`SyncGeo(ctx, old, next)` 的 old 分支终于被激活）。失败走现有 `geoFailed`（删就绪标记，不阻断）。

## 文件改动（5 个文件）

**1. `internal/dto/shop.go`** — 扩展 ShopInput：加 `ID int64` 和 8 个新指针字段；`ApplyTo` 补上对应赋值；新增 `HasChanges()`（所有指针字段做 OR 非空判断）。

**2. `internal/repository/shop.go`** — 新增 `ShopUpdate(ctx, id, in dto.ShopInput) error`：

```go
updates := make(map[string]any)
if in.Name != nil { updates["name"] = *in.Name }
// ... 每个非 nil 指针进 map，列名 type_id 等映射收敛在这一层
result := r.DB.WithContext(ctx).Model(&model.Shop{}).Where("id = ?", id).Updates(updates)
if result.RowsAffected == 0 {
    // MySQL 的 affected 是"变化的行"而非"匹配的行"：值完全相同也会返回 0
    // 所以二次 FindById 区分"不存在"和"无变化"
}
```

**3. `internal/service/shop.go`** — 新增 `ShopUpdate(ctx, id int64, in dto.ShopInput) error`，流程：读旧商铺（ErrRecordNotFound 透传）→ `next := *old; in.ApplyTo(&next)` → `validateShop(&next)` → 类型变了才查 `ShopTypeExists` → `repo.ShopUpdate` → `cache.Invalidate(ShopKeys(id))`（失败仅日志）→ `SyncGeo(ctx, old, &next)`（失败走 `geoFailed`）。顺手删掉 service/shop.go:167 那条过时注释。

**4. `internal/handler/shop.go`** — 新增 `ShopUpdate` handler：bind JSON → `in.ID <= 0 || !in.HasChanges()` 报 400 → 调 service → 错误映射复用现有三分类（`gorm.ErrRecordNotFound`→404、`ErrInvalidShopCreat`→400、其他→500）→ 成功返回 `{"success": true}`。

**5. `internal/handler/router.go`** — auth 组里加一行 `auth.PUT("/shop", shopHandler.ShopUpdate)`。

## 本步的教学点（写代码时会遇到的坑）

1. GORM struct 更新会吞零值 → 必须 `Updates(map)`；2. MySQL affected≠matched → RowsAffected==0 要二次确认；3. 缓存失效必须在 SQL 提交后（否则事务回滚缓存已白删）；4. GEOADD 天然是 upsert。

## 已知简化（故意不做，留给后续）

- 读 old → 写库之间没有进程锁/乐观锁，并发更新同一 id 理论上后写覆盖（go-dianping 用 geoMu 互斥，当前没有 WarmGeo 不急需）。
